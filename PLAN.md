## Правила кодера (обязательны, не рекомендации)

1. **Зелёный результат без мутации — иллюзия.** Тест, который нельзя уронить,
   ничего не проверяет. Каждый прогон обязан кончаться мутацией: снять защиту
   и убедиться, что тест это заметил. Если мутация не поймана — тест пустой.
2. **Правь причину, а не симптом.** Если тест протух из-за жёстко зашитых дат —
   чинить тест, а не подкручивать код под него.
3. **Не чинить то, что не сломано.** Изменил что-то — докажи мутацией, что защита
   теперь работает.
4. **Комментарий объясняет «почему», а не «что».** И не содержит иероглифов,
   мусорных символов и плейсхолдеров вида «TODO: описание».
5. **Всё общение и отчёты — на русском.**

## Пункт 1 (первый ход): GenerateNodeID выдаёт 32-битный ID — ВЫПОЛНЕН (commit 954af8e)

**Симптом:** на Cathedral `TestGenerateNodeID` падает
(`--- FAIL: TestGenerateNodeID`), на torquemada — зелёный. Тест flaky.

**Причина** (`internal/registry/registry.go`):

```go
func GenerateNodeID(pubkey string) string {
	h := fmt.Sprintf("%x", struct{ uint32 }{rand.Uint32()})
	return "node-" + h[:8]
}
```

- Берётся `uint32` — 4 байта, диапазон 2³² ≈ 4.3 млрд. Срез `h[:8]` отдаёт
  все 8 hex-символов, то есть 32 бита. По парадоксу дней рождения коллизии
  вероятны уже при ~10 тыс. узлов и почти гарантированы при ~100 тыс.
- Параметр `pubkey` принимается и **не используется** — идентификатор не привязан
  к владельцу ключа.
- `math/rand` вместо `crypto/rand` — для сетевых идентификаторов не годится.

**Что сделано:** расширено до 128 бит (16 hex), используется `crypto/rand`,
задействован `pubkey` в формировании ID через XOR с SHA-256 хешем публичного ключа.
Формат: `node-` + 32 hex chars (128 бит).

**Гейт:** `go test ./internal/registry/ -count=100` — ноль падений.
Плюс мутация: сузить обратно до 32 бит → тест обязан упасть.

## Пункт 2: закрепить найденное мутационное тестирование — ВЫПОЛНЕН

Создан обобщённый инструмент мутационного тестирования:
- `scripts/mutagen/main.go` — Go-программа, запускает мутации по всему пакету
- Мутации: инверсия сравнений, удаление проверок ошибок, инверсия булевых литералов,
  изменение констант, удаление вызовов функций
- Запуск: `mutagen -pkg ./internal/registry -test TestGenerateNodeID -v`

**Результаты прогона:**
- `internal/registry` (2 файла): 8 мутаций, PASS=7 FAIL=1 — найдена пустая проверка ошибки в `GenerateNodeID` (fallback на timestamp не тестируется)
- `internal/transport` (4 файла): 27 мутаций, PASS=21 FAIL=6 — тесты покрывают только константы и структуры, логика транспорта не защищена
- `internal/apptransport` (5 файлов): 61 мутация, PASS=49 FAIL=12 — заявленные 6 мутаций не охватывают все дыры

Инструмент интегрирован в workflow: после каждого изменения кода можно запустить
`mutagen -pkg ./path/to/pkg` для верификации, что тесты не стали пустыми.

**Следующий шаг:** устранить найденные вакуумные тесты (п.3 плана — план противоречий).

## Пункт 3: план противоречий (вместо плана на 10 пунктов)

Числовые 10 пунктов — карго-культ: план должен рождаться из измерений.
Каждый прогон: снять метрику → найти худшее → починить → доказать мутацией.

Приоритеты из замеров мутационного тестирования:
1. `internal/registry` — добавить тест для error path в `GenerateNodeID` (инъекция rand source)
2. `internal/transport` — написать настоящие тесты логики транспорта, а не только констант
3. `internal/apptransport` — закрыть 12 найденных дыр мутационным тестированием
